# TVBox for macOS

原生 SwiftUI + 内置开源 VLC 桌面影视客户端。此工程是独立实现的首版客户端，不是 Android TVBox 的完整兼容移植版。

## 运行

打开 `dist/Release/TVBox.app` 即可运行，也可将它复制到“应用程序”。通用包支持 Intel（x86_64）和 Apple Silicon，最低 macOS 13；另提供仅 Intel 的应用包。运行无需安装 IINA、VLC 或 Homebrew。

1. 点击“添加内容源”，填写 TVBox JSON 地址或选择本地 JSON / M3U / TXT 文件；可指定仅添加点播源或仅添加直播源，并填写自定义名称。
2. 在“发现”选择已保存的点播源，再选择该配置内的接口，浏览分类和搜索，打开详情后选线路和剧集。
3. “电视直播”有独立的直播源选择器，只加载当前选中的直播列表。切换直播源不会改变点播源或点播接口。
   右侧“列表 / 平铺”可切换紧凑频道列表与多列卡片，选择会保留到下次启动；分组、搜索和播放操作在两种展示中通用。
   播放画面左边的“选台”窄条在鼠标移入时展开，透明渐变频道栏支持搜索、直接切台；鼠标留在栏内保持展开，移出且无操作 3 秒后收起。直播与点播都可点击画面右下角“全屏”、双击视频画面或按 Control + Command + F 进入全屏；Esc 或“退出全屏”返回，直播全屏保留选台栏。
   默认按频道名称自动分类为央视、卫视、影视、少儿、体育等类别，“全部”按组分段展示，同组采用数字自然排序；CCTV1 与其高清版本等相近名称会靠在一起。可在直播页或左侧栏的分组选择中切换“自动分类 / 原始分组”、筛选分组并继续搜索，分类方式会记住。
   有节目单地址的频道显示日历按钮，可按日期查看预告；源提供可识别的回看模板时，期限内已播出的节目显示回看按钮，并可随时返回直播。
4. 在详情中收藏影片；播放进度自动存入“播放记录”。选“继续播放”可续播。
5. “打开视频”支持直接输入视频地址，也可从菜单打开本地文件。
6. “网络探测”可批量检测配置中的接口和订阅地址。选择范围、超时（3–15 秒）与并发数（2–8），点击“开始探测”；可停止、重测失败项、按耗时排序或筛选失败地址，并复制当前筛选的已完成结果。配置管理页也有入口。

未导入配置时显示 Blender 开放电影 Sintel 的官方预告片。示例依赖网络，不内置公共影视采集源。

## 支持范围

| 内容 | 状态 |
| --- | --- |
| 标准 TVBox JSON / JSON5 `sites`、`lives`、`urls` | 已支持；`urls` 子配置需手动选择 |
| 图片前缀 + `**` Base64 配置、纯 Base64、UTF-8 BOM | 已支持；不依赖响应的 MIME 类型 |
| `type: 1` JSON 采集接口 | 分类、分页、站内搜索、详情、多线路选集 |
| `type: 0` XML 采集接口 | 分类、分页、站内搜索、详情、CDATA 及多线路 |
| M3U、TXT `#genre#` 直播列表 | 分组、台标、多地址内嵌频道、常见 UA / Referer 请求头 |
| HLS / MP4 / MKV / FLV / MPEG-TS、HTTP 视频直链、本地视频 | 默认由应用内置 VLC 解码，启用可用的硬件解码 |
| HTTP-FLV 直播 | VLC 直接解码；系统投屏或自定义鉴权兼容通道仍可使用本机 HLS 封装 |
| 收藏、历史、断点续播、自动下一集 | 本机保存，历史最多 100 项 |
| 多个点播源和多个直播源 | 两份列表分别管理和选择；重启后恢复选择，每个点播源记住接口 |
| 批量网络探测 | 点播接口、直播订阅、子配置；HTTP 状态、耗时、错误分类、并发、取消及失败项重测 |
| 全屏、画中画、倍速 | 直播 / 点播统一全屏按钮、双击、Control + Command + F；Esc 返回，画中画与倍速保留 |
| 独立播放器、复制地址 | 内置 VideoLAN VLCKit 3.7.3；已移除外部 IINA 打开入口 |
| 播放错误诊断 | 中文区分 TLS、证书、网络、鉴权和失效地址；错误详情不含 URL 或凭据 |
| Android JAR / CSP、JS / Python 爬虫 | **未支持**，明确标记为“待适配” |
| `type: 4` 远程爬虫、加密配置 | **未支持** |
| `parses` 解析、网页嗅探、DRM、自定义 DNS / hosts | **未支持** |

仅导入含 JAR / CSP 源的配置时，可以查看配置及兼容状态，无法执行这些源。不能保证任意网上的 TVBox 地址均可使用。搜索限当前影视源。

0.1.2 增加播放错误诊断与公开演示自检入口。TLS 错误表示安全连接建立失败，不能仅凭这一提示确定是否证书过期。可用公开演示视频检查播放器链路；片源自身的证书或协议问题仍需维护者修复。

0.2.1 支持常见图片封装配置及 Base64 解码，并给网页响应、无效配置和视频清单提供明确提示。解开传输封装不等于能够执行配置里的爬虫：仅含 type 3 等不兼容点播接口时，会保留已选中的可用点播源，并在管理页显示兼容提示。AES、密码保护等其他加密格式仍未支持。

0.3.0 增加直播兼容模式：已知 FLV 地址直接走兼容通道；直播在系统播放器中遇到格式或服务器响应兼容错误时，会自动尝试本机封装。发布包自带约 1.7 MB 的独立封装工具，运行不依赖 Homebrew、系统 FFmpeg 或 IINA。它使用精简 FFmpeg 库，只复制受支持的音视频流，不执行转码；其他编码、失效源和服务器证书问题仍可能无法播放。首次连接需要缓冲数秒。

兼容服务只绑定本机回环地址，按会话随机路径提供临时 HLS 文件，保持有限的直播窗口。切换、停止或退出会终止工具并清理本次缓存；工具会检测父应用是否退出，避免应用异常结束后继续运行。

0.3.2 在直播线路出错时自动尝试同频道的其他不同地址，每轮仅尝试一次，全部失败后停止。播放页显示正在尝试的线路，可手动“下一条线路”或刷新直播列表；本次运行优先复用已加载成功的地址。原生线路连接等待最多 15 秒，兼容启动最多 20 秒，兼容媒体加载最多 15 秒；成功开始播放后不使用这些连接截止时间。停止、换台或手动选择会取消旧任务，避免旧线路错误干扰新频道。兼容组件的技术代码放入错误详情，无效数据和找不到媒体文件显示中文说明。所有地址都失效时仍需更新源；不会自动替换用户的直播源，也不会跳过证书校验。

0.3.1 优化频道列表和切换：同组、同名、相同请求头的重复频道合并成多条线路，保留不同地址；分组与搜索使用后台预计算索引，卡片按需构建。返回列表保留分组、搜索和当前频道位置，播放页可直接上一台 / 下一台。最近最多 8 个直播源的成功列表在内存缓存 5 分钟，手动刷新始终重新获取。配置只保存各源自己的内容，选择状态独立轻量保存，序列化和偏好写入使用后台串行队列，退出前完成待保存任务。

新地址追加保存，同一地址再次导入会更新已有源。自动识别会将综合配置中的点播接口和直播订阅分别保存；也可明确选择“仅点播源”或“仅直播源”。一个配置中的多个直播订阅可分别选择。配置管理支持重命名、刷新和移除；移除当前源时只在对应列表内回退选择。

旧版单配置自动迁移，收藏和历史保留各自的原始源信息。不同点播配置内即使接口 key 和影片 ID 一样，也不会混淆收藏与播放记录。配置失败不会修改现有源。本地配置中的相对路径按配置文件所在目录解析。

## 开发

源码包附带官方 VLCKit 二进制归档和 FFmpeg 源码。安装 Swift 6 及相应 Xcode Command Line Tools 后，可在 Intel Mac 直接编译：

```bash
bash scripts/build-app.sh
# Intel Mac 上默认生成 Intel 应用，也可显式指定：
bash scripts/build-app.sh intel
# 生成同时支持 Intel 和 Apple Silicon 的通用包：
bash scripts/build-app.sh --universal
bash scripts/test.sh
```

`build-app.sh` 生成 `.app`、应用图标、ad hoc 本机签名及 ZIP，同时调用 `build-remux.sh` 从随源码包附带的官方 FFmpeg 源码构建独立兼容工具。默认按本机架构构建，intel 指定 x86_64，--universal 分别编译 arm64 / x86_64 后合并；最低 macOS 13。内置 VLC、应用和直播辅助工具均检查目标架构、非系统外部依赖与完整签名。没有 Apple Developer 分发签名和公证，跨机器分发前需要用自己的开发者身份签名、公证。

### GitHub Actions 自动编译与发布

工作流文件：.github/workflows/macos-build.yml。将 Source 目录内的项目文件（包括隐藏的 .github 目录）放在 GitHub 仓库根目录；Package.swift 必须和 .github 同级。不要把 TVBox.app 或源码 ZIP 当成仓库源码上传。

| 版本 | GitHub 运行机 | 编译架构 | 产物 |
| --- | --- | --- | --- |
| Intel | macos-15-intel | 本机 x86_64 | TVBox-macOS-Intel.zip |
| Apple Silicon | macos-15 | 本机 arm64 | TVBox-macOS-AppleSilicon.zip |

每个运行机会先检查自身架构，校验官方依赖，运行 Core 测试，再编译应用和直播辅助工具、检查播放内核架构、执行 ad hoc 签名、验证 ZIP，并生成 SHA-256 文件。GitHub 当前的 Intel 与 ARM 标签见 [官方运行机文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job)。Actions 固定到已核验的提交版本。

推送 main / master 或提交 PR 会自动编译；也可打开仓库 Actions → Build macOS → Run workflow 手动运行。完成后在该次运行底部 Artifacts 下载 Intel 或 Apple Silicon 包，保留 14 天。工作流不合成 Universal 包，本机构建通用版仍可用 build-app.sh --universal。

首次上传到自己新建的空仓库，在 Source 目录执行（替换自己的仓库地址）：

```bash
git init
git add .
git commit -m "Add TVBox with macOS build workflow"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/TVBoxMac.git
git push -u origin main
```

VLC 的大归档已加入 .gitignore。缺少归档时脚本从 VideoLAN 官方地址下载固定版本，并验证 SHA-256；源码交付 ZIP 继续包含离线归档。FFmpeg 归档也会校验，缺失时从官方地址下载。Actions 缓存只保存这两份已校验归档，不依赖本机 Vendor 或 .build 缓存。

发布版本时先修改 Resources/Info.plist 的 CFBundleShortVersionString 与 CFBundleVersion，提交并推送。Tag 必须等于 v + CFBundleShortVersionString，例如当前版本：

```bash
git tag v0.7.1
git push origin v0.7.1
```

两种架构全部成功后，工作流使用 GitHub 自动提供的 GITHUB_TOKEN 创建 Release，附上两个安装 ZIP 及 SHA-256。重新运行同一 Tag 会更新对应附件；无需额外配置个人访问令牌。Release 任务单独申请 contents: write；仓库或组织若限制此权限，需要允许该任务写入 Releases。普通 PR 构建保持只读权限。

当前产物沿用本机 ad hoc 签名，没有 Apple Developer 分发签名与公证；如需公证分发，应另外配置开发者证书与 notarytool 凭据。本工作流尚未在你的 GitHub 仓库实际执行，首轮运行结果以 Actions 日志为准。

### 本地端到端验证

生成一个 30 秒的无版权测试画面（需安装 FFmpeg），启动仅监听本机的测试服务：

```bash
mkdir -p .build
ffmpeg -f lavfi -i 'testsrc2=size=640x360:rate=24' -f lavfi -i 'sine=frequency=440:sample_rate=44100' -t 30 -c:v libx264 -pix_fmt yuv420p -c:a aac -movflags +faststart .build/test.mp4
python3 scripts/fixture-server.py
```

在 App 导入 `http://127.0.0.1:18791/config.json`，可以验证 JSON/XML 分类、搜索、详情选集、直播、兼容提示、收藏和续播。单元测试通过 `URLProtocol` 模拟网络，不需要在线影视接口。

多源验证可分别导入 `/config-a.json`、`/config-b.json`（选择仅点播源），再导入 `/live-a.m3u`、`/live-b.m3u`（选择仅直播源）。脚本 `python3 scripts/prepare-validation-app.py` 会生成独立 bundle identifier 的验证 App，走普通启动路径，源列表与正式 App 隔离。

直播地址的 `$LR•…『线路N』` 等明确线路备注会在解析时移除；不会按任意 `$` 字符截断 URL，查询鉴权中的普通 `$` 和百分号编码保持原样。该处理同时用于新导入和已保存的内嵌频道。

0.4.1 的探测结果默认按 HTTP 响应耗时从低到高排序，正常项在前，失败和未完成项在后。同耗时保持配置顺序。每轮完成后自动恢复耗时排序；按点播接口、直播订阅和子配置分别给出一个网络首选及最多两个备选。仅 HTTP 2xx 正常响应参与推荐，当前版本不支持的点播接口不参与；部分停止时只依据已完成结果，不把未测地址当成慢地址。推荐基于各地址最近一次网络响应，不代表内容或播放验证，也不会自动修改当前源选择。结果行及复制报告包含对应的首选 / 备选标记。

0.4.2 在配置管理中同步显示本次运行的探测结果：直播订阅列表文字、子配置名称及点播接口后附 `【123ms】`。未探测不显示，失败或取消单独标记，悬停查看 HTTP 状态及耗时；按完整地址、类别和请求头匹配，地址或授权信息变化后不会沿用旧数值。结果跟随后台探测实时更新，仍只在本次运行保留。

0.4.3 在配置管理的“直播源”标题旁加入排序选择，默认“时延从低到高”，也可返回“原始顺序”。正常响应的直播源按最新探测耗时排列，失败、未测及取消项放后，同耗时保持配置顺序。直播页的源选择器同步排序并显示正常项的 `【123ms】`。排序只影响展示，不修改已保存的源顺序或当前选择；排序偏好会保留到下次启动。

## 0.7.1 源复制与修改

配置管理中的点播源与直播源均提供复制按钮，也可在行末菜单选择“复制地址”或“修改名称 / 地址”。复制完整地址，保留鉴权查询参数；列表展示仍隐藏查询参数与用户信息。编辑名称和地址后点击“保存修改”：名称单独修改无需联网，新地址会先校验，再原位替换，不追加副本，不改变源 ID、当前选择、收藏或历史的作用域。修改非当前源不会切换当前源。

失败、取消、类型不匹配或与已有地址重复时保留原数据；验证期间源被移除或另有更新时，不提交过期结果。修改已选源地址会刷新对应片库 / 频道；仅改名不中断播放。单个直播订阅保留原请求头与节目单默认信息，并继续支持探测与刷新。一个地址返回多个直播来源时，使用“添加直播源”导入，或直接填写其中一个订阅地址。

源管理保存 / 取消的隔离验证：启动 scripts/fixture-server.py，运行 python3 scripts/check-source-edit.py。使用独立偏好域和独立测试剪贴板，不改动正式源或用户剪贴板。

## 0.7.0 独立播放与 Intel

普通播放由应用自己的 VLCKit.framework 提供，不调用外部播放器，也不读取本机 IINA 的库或设置。FLV、MKV 与 MPEG-TS 由 VLC 直接播放；新频道使用独立渲染视图，旧输入的异步停止不能移除新频道画面。全屏在窗口之间移动当前容器和渲染视图，不重新连接片源。暂停状态下连续方向键仍按每次 3 秒累积；VLC 暂停时不立即更新底层时间通知，因此控制条先显示已请求的位置，在解码器确认后同步实际进度。

UA / Referer 传给 VLC；Cookie、Authorization 和其他自定义 HTTP 请求头使用系统兼容通道，避免静默丢失鉴权。打开 AirPlay 菜单或画中画时也切换系统播放通道，点播保留进度、暂停、倍速、音量；控制条中的“返回 VLC”可恢复内置播放。带特殊鉴权头的地址仍需兼容通道。电视端播放能力取决于接收设备和片源，未在实际电视上验证。

VLC 初始连接失败会自动重试一次，再失败尝试同频道备用线路。必须检测到实际音视频轨道才算连接成功；HTML / 错误网页不能提前取消连接超时。普通播放不再生成本机转封装视频缓存；配置、收藏与历史沿用原存储。

当前播放回归使用 scripts/check-vlc-playback.py，分别传入 arm64 / x86_64。测试素材为本机生成的 test.mp4、test.flv、test.mkv、test-mpeg2.ts，放在 .build 中，并启动 scripts/fixture-server.py。Intel 测试在 Apple Silicon 上可通过已安装的 Rosetta 执行 x86_64 二进制；这不能代替 Intel 物理硬件和显卡上的测试。旧版 check-fullscreen.swift / check-tls-retry.swift 保留为系统 AVPlayer 通道的历史测试参考，默认 VLC 的验证结果见 VALIDATION.md。

## 数据与结构（以下为历史版本说明）

0.6.5 修复影片卡片海报重叠：卡片容器统一保持 0.70 宽高比，海报在容器实际尺寸内按比例填充并裁剪；横版、超宽、超长图片不再以自身比例撑大网格单元。加载占位与成功图片共用尺寸，影片标题和副标题跟随列宽。发现、收藏、播放历史共用此卡片，详情页海报继续使用原有固定尺寸。

0.6.4 将左右方向键的每步跳转改为 3 秒；连按累积跳转目标，长按接受系统重复按键事件，向前 / 向后均可连续调整。边界、焦点保护、暂停状态与倍速保持沿用 0.6.3 的逻辑。

0.6.3 支持左方向键后退 15 秒、右方向键快进 15 秒，窗口和全屏均可使用；适用于点播与有固定时长的节目回看，普通直播不跳转。连续按键累积目标并限制在视频起止范围，保留暂停状态和倍速；操作后显示控制条。点击视频可将键盘焦点交给播放器，输入框 / 滑杆 / 表格等控件拥有焦点或菜单跟踪时保留原有方向键行为；带 Command、Control、Option、Shift 的方向键不拦截。

0.6.2 将全屏 / 退出全屏按钮放入与倍速、音量、画中画、AirPlay 相同的控制条，共享显示状态、鼠标悬停和淡出动画。播放时无操作 3 秒整条隐藏，移动鼠标同时出现；暂停、拖动进度、鼠标停留在任一控制按钮或打开 AirPlay 设备菜单时保持显示。加载或报错时全屏入口仍可使用。

0.6.1 统一播放控制条图标的 18 pt 图形边界、32 pt 按钮高度和 10 pt 主间距；倍速、音量、画中画、AirPlay 与全屏垂直居中。全屏按钮与控制条共用底部留白和高度，右侧预留空间随统一宽度计算，文字统一为 11 pt。AirPlay 保留原生设备选择器，仅调整展示尺寸。

0.6.0 在窗口 / 全屏播放控制条加入“投屏”入口，使用 macOS 的 AVRoutePickerView 为当前 AVPlayer 选择 AirPlay 电视、Apple TV 或其他兼容接收设备；系统处理发现、配对和设备选择。Mac 与电视连接到同一网络并开启电视的 AirPlay 后，点击图标选择设备；在同一菜单选择此 Mac 可返回本机播放。打开设备列表时控制条保持显示，系统确认外部播放后显示“投屏中”和画面状态提示。全屏切换和切集继续使用同一个 AVPlayer。

实际可投内容取决于接收设备、视频格式与片源访问条件；本机兼容直播使用回环 HLS 服务，电视不能直接访问该回环地址，没有新增局域网视频转发服务。此类线路如无法投放，可使用 macOS 屏幕镜像。当前验证环境只发现本机，已验证系统设备菜单和播放器绑定，电视端出画与配对需连接兼容接收设备验证。

0.5.5 在视频播放，以及配置、订阅、影视接口和节目单取数遇到 TLS 连接失败时，等待 0.7 秒后自动重试一次，原地址及请求头保持不变。重试失败显示中文说明，不再直接展示英文 TLS 错误；证书校验失败保留单独原因。直播每条线路最多自动重试一次，随后按原逻辑尝试备用线路。点播 / 回看重连保留进度、暂停状态和所选倍速，直播重连回到实时位置。停止、换台或切源会取消旧请求的重试，重复错误回调不会无限重连。批量网络探测仍报告实际探测结果。

0.5.4 根据真实崩溃栈修复全屏切换：不再使用 AVPlayerView 的系统浮动控制条，改由单个持久 NSView / AVPlayerLayer 承载画面，窗口间只移动该视图，AVPlayer、当前 item 和渲染层绑定保持不变。当前展示模式决定哪个容器能接管，旧容器的延迟更新和拆除不能抢回或移走画面。独立控制条提供暂停、进度拖动、前后 15 秒、音量、静音、倍速和公开 AVPictureInPictureController 画中画接口，播放结束可重新播放；播放时闲置 3 秒淡出，移动鼠标或暂停时显示。进度更新仅刷新控制条，频道列表不跟随时钟重绘。

直播 / 点播均提供画面右下角和播放页顶部全屏按钮，播放菜单提供 Control + Command + F；视频区域双击触发全屏，底部控制区不参与双击识别。快捷键仅在当前播放器所在窗口处理，进入全屏后 Esc 即使在频道搜索框编辑时也可退出。全屏复用 AVPlayer 与当前 item、速率、时钟及画面渲染层。点播切集时保留全屏，停止播放退出全屏，结束应用时立即清理。进入 / 退出系统动画期间的重复请求按窗口生命周期排队；旧窗口回调不会影响新窗口，进入失败会清理并回到原播放页。

`scripts/check-live-overlay.py` 额外编译 `check-fullscreen.swift` 和 `check-tls-retry.swift`，在隔离窗口里验证真实视频的暂停 / 倍速 / 进度、TLS 重试及取消、内嵌与全屏单一绑定、下一集、排队退出、重复退出、失败恢复和旧回调隔离，渲染 `.build/fullscreen-*.png`。脚本中的系统 Spaces 转场由注入的窗口驱动替代，不发送鼠标或键盘输入；0.5.4 另通过桌面工具实际验证系统全屏、Esc 返回及全屏选台，见 VALIDATION.md。

0.5.2 将直播选台浮层从 220–290 pt 缩窄为 190–220 pt（按画面宽度 22% 取值），同时缩小左右内边距及图标间距。分组数量固定宽度、勾选列对齐，节目单标题保持单行；透明背景与 3 秒收起逻辑沿用现有实现。

0.5.1 的频道自动分类基于明确的频道名称关键字，名称未识别时使用原分组关键字，仍未识别则归入“其他频道”；当前规则为单一分类，央视和卫视等明确家族标识优先。同组按名称和数字自然排序，忽略空格、标点与 CCTV / CGTN 前缀装饰，排序相同时保留输入顺序。分类、排序和搜索索引均在现有后台频道索引构建时计算，不在滚动过程中重算。原始分组和频道 ID 不变，相近名称不被合并；播放地址、鉴权头及节目单元数据原样保留。分类方式存入 `live.channel-grouping.v1`，切换方式会清除不适用的组筛选，切源保留分类方式。分组名称为“全部”的原始频道也会显示。

0.5.0 加入直播透明浮层选台与节目单。频道栏采用懒加载列表，搜索在后台使用现有索引；展开 / 收起不重新连接或替换 AVPlayer。全屏窗口复用同一播放器和浮层；收起后仅左侧窄条接收鼠标事件，其余区域保留原生播放控制。3 秒计时从鼠标离开栏内开始，移回取消计时，离开后的操作会重新计时。

节目单按点击加载，解析在独立 actor 执行；最多缓存 4 份响应、5 分钟，按完整 URL 和请求头区分。支持 TVBox lives / 根节点的 `epg`（`{name}` / `{date}`）以及 M3U 头部 `x-tvg-url` / `url-tvg` 的未压缩 XMLTV；按 `tvg-id` 精确匹配，缺少 ID 时使用不歧义的频道名。TVBox JSON 支持 `channel_name`、`date`、`epg_data[{start,end,title}]`。节目单失败只在左侧栏内显示，不中断视频，也不加载未点击频道的节目单。

M3U 回看支持明确的 `catchup="default" / "append" / "shift"`、`catchup-source`、`catchup-days`、`catchup-correction`；支持 `{utc}`、`${start}`、`{utcend}`、`${end}`、`{lutc}`、`${now}`、`${timestamp}`、`{duration}`、`{catchup-id}` 及 `{Y}/{m}/{d}/{H}/{M}/{S}`。未识别模式或占位符不会生成播放地址。仅开始时间已过去、结束时间已知且在源给定回看窗口内的节目显示播放按钮，未来节目仅为预告。没有源数据时不生成节目单或推断回看地址；旧订阅需刷新原配置或重新导入才能读取此前未保存的元数据。XMLTV gzip 文件、Xtream / Flussonic 自动回看模式及自定义格式化占位符暂未支持。

本地验证：运行 `python3 scripts/fixture-server.py` 后执行 `python3 scripts/check-live-overlay.py`，使用独立测试偏好和本机视频，检查生产 3 秒计时、移回取消、操作重置、1,000 频道切台、回看及返回直播，并将程序自己的浮层离屏渲染为 `.build/live-overlay-*.png`，不截取或操作桌面窗口。

0.4.0 的网络探测只检查已配置的 HTTP / HTTPS 接口和订阅，不递归访问子配置、不展开频道播放地址、不执行爬虫。按地址、类别和请求头合并重复项；不同授权信息分开探测。默认 6 并发、8 秒超时，HEAD 不受支持（405 / 501）时在同一超时预算内尝试 GET，系统报告响应后即取消读取，不下载完整订阅。HTTP 2xx / 3xx 表示网络响应正常，不能据此判断接口内容有效或视频可播放；403 / 404 等有响应的错误和 DNS、连接超时、证书错误分别显示。结果只在本次运行保留，离开页面后任务继续运行，可返回查看。复制的报告使用表格文本，地址列隐藏用户信息、查询参数和片段。

真实本机服务验证：启动 `scripts/fixture-server.py` 后运行 `python3 scripts/check-network-probe.py`。可选 `--render` 将程序自己的测试页面离屏渲染为图片（不会截取或操作桌面窗口）。脚本使用 Release 网络代码与实际界面状态模型，只允许回环测试地址。

多源列表保存在当前用户 UserDefaults 域 `local.tvboxmac` 的 `sourceLibrary.v1` 中；当前源与各点播接口选择独立存入 `sourceSelection.v1`，优先于旧列表中的选择。收藏和记录同域保存，没有云同步。接口可能包含访问令牌，当前按普通偏好数据保存，首版不提供凭据加密存储。`--ui-test` 使用独立测试域，可配合 `--ui-test-suite 名称` 指定隔离的验证环境。
